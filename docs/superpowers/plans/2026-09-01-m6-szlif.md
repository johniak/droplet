# M6 — Szlif: plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Z „działa" do „przyjemność używania": animacje, tryb offline, sortowania i widoki, ludzkie komunikaty błędów, ikona/splash — zamknięte tygodniem realnego używania i feedbackiem użytkownika.

**Architecture:** Wyłącznie klient Flutter (backend bez zmian). Animacje na wbudowanych mechanizmach (`Hero`, implicit animations — bez dodatkowych zależności); offline jako cache JSON w katalogu dokumentów aplikacji; sortowanie/filtry client-side na pełnej liście z `gamesProvider`.

**Tech Stack:** dodatkowo: `path_provider`, `flutter_launcher_icons` (dev), `disk_space_plus` (wolne miejsce; jeśli pakiet nie działa na docelowym Androidzie — pomijamy ostrzeżenie o miejscu, funkcja jest opcjonalna).

**Spec:** `docs/superpowers/specs/2026-09-01-droplet-design.md` (§3.7, §4)

## Global Constraints

- Obowiązują Global Constraints z M4/M5 — w tym **pokrycie 100%** (`./scripts/check_coverage_app.sh` przy każdym zadaniu) i **zielone suity e2e** (`scripts/e2e_backend.sh` + `scripts/e2e_app.sh`); nowa logika (cache offline, sortowanie, humanizacja błędów) wchodzi z testami, a zmiany UI nie mogą wywrócić istniejących testów integracyjnych.
- Zero nowych ekranów — tylko dopracowanie istniejących.
- Każda animacja ≤ 300 ms; brak animacji blokujących interakcję.
- **Przed każdym taskiem UI wykonawca ładuje skill `frontend-design:frontend-design`.**
- Nowe zależności od pluginów (wolne miejsce) idą przez porty z M5 (`DownloaderPort`), nie bezpośrednio do logiki — lista plików z `// coverage:ignore-file` się nie rozszerza.
- Biegi częściowe bez `--coverage`; bramką jest `./scripts/check_coverage_app.sh` na końcu zadania.

### Task 2: Tryb offline

**Files:**
- Create: `app/lib/core/cache/library_cache.dart`
- Modify: `app/lib/features/library/providers.dart`, `app/lib/features/library/library_screen.dart`
- Test: `app/test/core/library_cache_test.dart`

**Interfaces:**
- Produces:

```dart
class LibraryCache {
  LibraryCache(this.directory);                    // katalog (w testach tmp)
  Future<void> save(List<SystemModel> systems, List<GameSummary> games);
  Future<CachedLibrary?> load();                   // null gdy brak pliku
}
class CachedLibrary { List<SystemModel> systems; List<GameSummary> games; DateTime savedAt; }
class LibrarySnapshot { List<SystemModel> systems; List<GameSummary> games; bool fromCache; Set<int> previousIds; }
final libraryCacheProvider = Provider<LibraryCache>(...);            // katalog z path_provider
final librarySnapshotProvider = FutureProvider<LibrarySnapshot>(...); // JEDNO źródło: sieć albo cache
final isOfflineProvider = Provider<bool>(
  (ref) => ref.watch(librarySnapshotProvider).valueOrNull?.fromCache ?? false);
```

  - `librarySnapshotProvider`: pobiera systemy + wszystkie strony gier; po sukcesie `cache.save(...)` i `fromCache=false`; przy `DioException` (błąd sieci) → `cache.load()` → `fromCache=true`, a przy braku cache — rethrow. `previousIds` = id gier z cache sprzed odświeżenia (używa Task 4 „co nowego"). `gamesProvider`/`systemsProvider` z M4 stają się cienkimi projekcjami snapshotu (istniejące testy nadpisują je dalej tak samo). Stan offline jest **wyprowadzony** ze snapshotu, nie ustawiany z wnętrza innego provider'a (Riverpod nie pozwala modyfikować provider'ów w trakcie inicjalizacji innego).
  - `LibraryScreen`: gdy `isOffline` — `MaterialBanner` „Tryb offline — pokazuję ostatnio pobraną bibliotekę"; akcje wymagające sieci (pobieranie) wyłączone.
  - Wymaga to serializacji zwrotnej: dopisz `toJson()` do `SystemModel` i `GameSummary` (lustrzane do `fromJson`) — z testem roundtrip w `models_test.dart`.
  - Test provider'a (`test/features/library_snapshot_test.dart`, `ProviderContainer` z nadpisanym `apiClientFactoryProvider` i `libraryCacheProvider` na katalog tmp): (1) sukces → zapis do cache, `fromCache=false`; (2) fake rzucający `DioException(connectionError)` + cache z poprzedniego biegu → `fromCache=true`, `isOfflineProvider == true`; (3) błąd sieci bez cache → provider w stanie błędu.

**Interfaces:**
- Produces:

Czysta funkcja `newGameCount(Set<int> previous, List<GameSummary> current) -> int` z testem (pusty `previous` = pierwszy bieg → 0, nie „wszystko nowe").
  - Ikona: 1024×1024 PNG — ciemne tło `#0E1116`, glif kropli w akcencie `#3FB6F0`. Generowana deterministycznie skryptem `scripts/make_icon.py` (Pillow: koło + trójkąt jako kropla, lekki gradient) — commitowany skrypt i wynik; Jan może później podmienić plik na własny projekt bez zmian w kodzie. `flutter_launcher_icons` generuje adaptive icon (`adaptive_icon_background: "#0E1116"`, `adaptive_icon_foreground` z marginesem); natywny splash: `android:windowBackground` w kolorze `kBg`.
